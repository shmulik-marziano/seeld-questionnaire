# Decisions Log

A record of every decision Claude Code made on its own (not explicitly stated in the project spec).

## Phase 1

### D-001: Repo cleanup of unrelated NOA project files
- **Date:** 2026-04-25
- **Context:** The repo `seeld-questionnaire` contained 4 files from a different project (NOA insurance questionnaire) committed by the user in December 2025.
- **Decision:** Deleted `START_NOW.md`, `SUPABASE_SCHEMA.sql`, `page.tsx`, `questionnaire-data.ts` from the working tree on branch `claude/samuel-phase-1-mvp-GiGjW` only. They remain on `main` and in git history.
- **Reason:** Per the spec rule of "no domain-specific code in Shmuel" and explicit user approval (option A).

### D-002: Workspace package naming convention `@shmuel/*`
- **Date:** 2026-04-25
- **Context:** Spec says project name is `shmuel`; workspace packages need a scope.
- **Decision:** All internal packages use the `@shmuel/` npm scope (e.g. `@shmuel/web`, `@shmuel/memory-engine`).
- **Reason:** Standard pnpm monorepo convention; avoids name collisions with public npm packages; matches project name.

### D-003: pnpm version pinned to 9.12.3, Node ≥20
- **Date:** 2026-04-25
- **Context:** Spec says "use pnpm" but does not specify version.
- **Decision:** Pinned `packageManager: pnpm@9.12.3` in root package.json; `engines.node: >=20.0.0`.
- **Reason:** Latest stable pnpm 9.x; Node 20 is current LTS and required by Next.js 14.

### D-004: Biome 1.9.4 instead of latest 2.x
- **Date:** 2026-04-25
- **Context:** Biome is the chosen linter.
- **Decision:** Pinned to `^1.9.4`.
- **Reason:** Stable, mature; 2.x has breaking config changes.

### D-005: Hand-authored database.types.ts
- **Date:** 2026-04-25
- **Context:** Supabase TypeScript types are normally generated by `supabase gen types`. We can't run that here without DB credentials.
- **Decision:** Wrote `apps/web/lib/supabase/database.types.ts` by hand, matching the migrations exactly. Added a `supabase:types` script that will overwrite it once you run it.
- **Reason:** The web app needs typed Supabase queries before the user can run the script. This unblocks development and gets replaced cleanly later.

### D-006: Memory relevance via keyword overlap (not embeddings) in Phase 1
- **Date:** 2026-04-25
- **Context:** Spec mentions `embedding vector(1536)` on `memory_facts` but doesn't say what to do for relevance in Phase 1.
- **Decision:** `loadRelevantFacts` uses token overlap + category boosts. Embedding column exists in schema but is unused in Phase 1.
- **Reason:** Avoids the cost and complexity of an embedding pipeline before we have any users. Swap to embeddings in Phase 2.

### D-007: Pre-create assistant message row before streaming
- **Date:** 2026-04-25
- **Context:** Streaming + persistence ordering matters for the regenerate/edit flows.
- **Decision:** `/api/chat` inserts the assistant message with `status='streaming'` BEFORE opening the SSE stream, then updates content/status when done.
- **Reason:** Lets us return the row id immediately to the client and keeps the foreign-key model consistent even if the stream is interrupted.

### D-008: SSE format for chat streaming, not Vercel AI SDK
- **Date:** 2026-04-25
- **Context:** Spec says "streaming like Claude" but doesn't pick a transport.
- **Decision:** Plain `text/event-stream` with explicit `event:`/`data:` framing. No Vercel AI SDK dependency.
- **Reason:** One fewer dependency, full control over events (`meta`/`delta`/`done`/`error`), trivial to consume from any client (including the future mobile/desktop apps).

### D-009: Plan limit signaling via HTTP 402
- **Date:** 2026-04-25
- **Context:** Free users hitting their daily message cap need to see an upgrade nudge.
- **Decision:** `/api/chat` returns `402 Payment Required` with `{ error: 'plan_limit', plan, limit }`; client surfaces a toast pointing at /billing.
- **Reason:** 402 is the semantically correct status for "you need to pay"; simpler than a custom error envelope.

### D-010: Tauri loads the live URL, no offline mode
- **Date:** 2026-04-25
- **Context:** Spec says the desktop app should be a wrapper around shmuel.ai.
- **Decision:** Tauri webview points directly at `https://shmuel.ai`. Local `dist/index.html` only redirects there, used as a placeholder so Tauri's bundle config doesn't complain.
- **Reason:** Matches the spec ("...שטוען את הכתובת"); zero divergence between web and desktop; updates roll out instantly.

### D-011: Updater endpoint returns 204 in Phase 1
- **Date:** 2026-04-25
- **Context:** Tauri config references `/api/updater/{target}/{arch}/{version}` but we have no signed releases yet.
- **Decision:** Stub route returns 204 (no update) until the user produces signed builds.
- **Reason:** Tauri tolerates 204; clients won't error; nothing else needs to ship to make the desktop app work.

### D-012: Admin-only price-to-plan map via env
- **Date:** 2026-04-25
- **Context:** Stripe gives us price ids; we need to map them back to plan slugs in the webhook.
- **Decision:** Read `NEXT_PUBLIC_STRIPE_PRICE_BASIC_MONTHLY` directly in `lib/stripe.ts` and `webhook/route.ts`. No hard-coded test ids.
- **Reason:** One env var change is enough to switch between test and live Stripe modes.

### D-013: 7-day trial on basic plan
- **Date:** 2026-04-25
- **Context:** Spec says "ניסיון חינם" but doesn't pick a length.
- **Decision:** 7 days, set in Stripe checkout `subscription_data.trial_period_days`.
- **Reason:** Industry standard for $20/month-class consumer SaaS.

### D-014: Profile + behavior + free subscription auto-created on signup
- **Date:** 2026-04-25
- **Context:** Without these rows, /api/chat would fail on first request.
- **Decision:** `handle_new_user()` trigger inserts into `profiles`, `behavior_patterns`, and `subscriptions(plan='free')` atomically.
- **Reason:** No manual onboarding step; eliminates a class of "row missing" 500s.

### D-015: Sentry init in dedicated config files, not Next.js auto-instrumentation
- **Date:** 2026-04-25
- **Context:** Spec says "Sentry" but doesn't specify integration depth.
- **Decision:** `sentry.client.config.ts` + `sentry.server.config.ts`, both gated on `NODE_ENV === 'production'`. No source-map upload wired up yet.
- **Reason:** Captures errors in prod without slowing local dev; source maps can be added later via the Vercel integration.
